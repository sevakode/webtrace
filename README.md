# WebTrace

Прототип приложения для iOS и Android: вставить HTTP/HTTPS-ссылку, исследовать сайт во встроенном браузере, сохранить наблюдения в ZIP для последующего анализа.

## Запуск

Нужны Node.js, Xcode + CocoaPods для iOS; JDK 17 и Android SDK 36 для Android. Для тестов нужен Google Chrome. Native-проекты включены в репозиторий.

Скопируй адрес репозитория через **Code** на GitHub и подставь его вместо `<repository-url>`.

```sh
git clone "<repository-url>" webtrace
cd webtrace
npm ci
npm run recorder
# Зависимости iOS
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer pod install --project-directory=ios
# iOS Simulator
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer npx expo run:ios
# Android на macOS с установленными через Homebrew JDK/SDK:
# предварительно запустить эмулятор или подключить телефон с USB debugging
. scripts/android-env.sh
npx expo run:android
```

В Xcode открывать `ios/webtrace.xcworkspace`. Для установки на физический iPhone см. [пошаговую инструкцию](INSTALL_IPHONE.md): выбрать свою signing team и конфигурацию Release для работы без Metro. Магазинная публикация и signing для распространения не настроены.

`scripts/android-env.sh` — помощник для macOS/Homebrew: он задаёт JAVA_HOME и пути Android SDK в текущей оболочке. На другом окружении настрой эти переменные под свою установку и запускай `npx expo run:android` напрямую. Для обычного клонирования `expo prebuild` не требуется; он нужен при намеренной перегенерации native-проектов.

## Как пользоваться

1. Вставить ссылку, нажать «Открыть». Запись начинается при открытии WebView.
2. Пройти сценарий сайта. Вкладки «Диплинки» и «События» показывают поступившие данные; браузер при переключении вкладок остаётся смонтированным.
3. «Завершить и сохранить ZIP» сохраняет снимок текущей страницы, по переключателю завершает запись с ограниченным ожиданием уже начатых ответов, затем нативно загружает доступные статические ресурсы и открывает системное меню отправки.
4. Передать ZIP в чат и попросить анализ по `ANALYZE.md`.

Сессия до экспорта хранится в памяти: перед закрытием приложения сохранить ZIP. После сохранения можно открыть новую ссылку. Сохранённые архивы находятся в Documents приложения.

## Что реализовано

- Исходная ссылка, наблюдаемые навигации WebView, история SPA, клики/submit/change без значений полей.
- Схемы приложений из ссылок, метатегов, `data-deeplink`, inline JS, доступных текстовых ответов и повторно загруженных скриптов; вложенные URL-параметры до двух уровней.
- Попытки внешних переходов фиксируются и блокируются: приложение не отдаёт управление другой программе. Это меняет поведение сценариев, которые ожидают возврат из внешнего приложения.
- fetch/XHR: URL, метод, статус, стек; доступные тела ответов. WebSocket: подключение и размеры сообщений, без содержимого.
- setTimeout/setInterval: задержка, callback, стек, первые 20 срабатываний; отмены таймеров.
- Inline-скрипты, HTML-снимки, список ресурсов и Resource Timing. Повторная загрузка доступных статических ресурсов через GET. Binary-файлы сохраняются как байты. Если WebView не отдал статический ресурс, native-resource-refetch пробует прямой GET без cookies WebView (до 60 ресурсов, до 8 МиБ на файл, 16 МиБ суммарно, 45 секунд); это может быть другая публичная версия файла.
- HTTP-ошибки, JS-ошибки, ограничения и пропуски захвата.
- Локальный ZIP, обзорный отчёт с фактами и шаблон запроса для анализа. Встроенный ИИ и сервер не нужны.

## Состав ZIP

`session.json`, `events.jsonl`, `links.json`, `links-raw.json`, `deeplinks.json`, `navigation.json`, `call-sites.json`, `timers.json`, `network.json`, `manifest.json`, `coverage.json`, `report.md`, `ANALYZE.md`, `files/`.

В `manifest.json` для каждого файла есть исходный URL, путь, событие, способ получения и признак усечения. `resource-refetch` — повторный ответ, не оригинальный перехваченный файл. Имена файлов генерируются приложением, пути со страницы не используются. Схема событий: `protocol`, `id`, `at` (Unix ms), `page`, `kind`, `data`; у JS-событий дополнительно `elapsed` (performance.now).

## Пределы покрытия

Это инструмент наблюдения, а не способ гарантированно скачать весь сайт. Не загруженные ветки кода, серверная логика и все произвольные вызовы функций недоступны. Обфускация не препятствует наблюдению многих браузерных API, но исходные имена и структуру программы не восстанавливает.

На Android ранняя JS-инъекция экспериментальна. iOS использует WKWebView. Промежуточные HTTP-редиректы, ранние действия, cross-origin фреймы, workers, service workers, WebAssembly и закрытый Shadow DOM могут быть пропущены. Антиотладка может обнаружить перехватчики или остановить JS. Это не обещание обхода защит.

Universal Links/App Links не подтверждаются автоматически. HTTP/HTTPS-ссылки помечены как непроверенные. Просроченная ссылка не оживляется; сохраняется доступная страница и ошибки. HTTP 410 сам по себе не доказывает причину истечения срока конкретного токена.

На документ: 512 КиБ на файл, 12 МиБ на тела, 15000 событий, статические GET через нативный загрузчик после остановки записи; на сессию: 20000 событий и 24 МиБ сериализованных данных. Остановка записи ждёт до 6 секунд; нативная догрузка — до 45 секунд. Усечённые файлы и отсутствующие полные копии отмечаются в coverage.json. CORS может запретить загрузку ресурса. GET потенциально может иметь побочный эффект на неправильно устроенном сайте.

Секреты могут присутствовать в URL, HTML и ответах API. Cookie/header/password поля отдельно не записываются; полной очистки персональных данных нет. Автоматической отправки нет. Страница может подделать bridge-события: архив не является защищённым журналом аудита. Код и инструкции внутри него следует рассматривать как недоверенные данные.

## Проверки

```sh
npm test
npm run typecheck
npx expo install --check
npm run fixture
```

Тест использует установленный Google Chrome в headless-режиме и локальный HTTP-сайт. Проверяет действия, fetch/XHR без повторения API-запросов, таймеры, динамические диплинки, вложенные URL, static-resource GET, сохранение файлов, усечение большого ответа, HTTP 410, остановку записи, валидацию bridge и безопасные пути ZIP. Создаёт `../sample-session.zip` с синтетическими данными.

`src/recorder.js` — исходник внедряемого сборщика; `npm run recorder` создаёт `src/recorder-source.json`. Сборщик передаётся в WebView как исходный текст: нельзя заменять на сериализацию преобразованной Metro-функции через toString.

Документация платформ: [React Native WebView](https://github.com/react-native-webview/react-native-webview/blob/master/docs/Reference.md), [Expo FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/), [React Native Android setup](https://reactnative.dev/docs/set-up-your-environment).

## Классификация ссылок и повторный анализ

Ссылки имеют category: app-candidate, web, template, resource или technical. Ни кандидат, ни attempted не доказывают успешного открытия приложения. Строки `${...}` остаются шаблонами. Исходные наблюдения доступны в links-raw.json. Крупные статические файлы идут через native loader и не проходят маленький WebView bridge; его лимит сохранён.

Для переразбора старого архива: `npx tsx scripts/enrich-archive.ts input.zip output.zip`. Флаг `--fetch-static` отдельно разрешает новые GET ранее наблюдавшихся статических ресурсов. Старые времена сессии сохраняются; новые ответы получают собственные timestamps и source. API/платёжные запросы не воспроизводятся.
